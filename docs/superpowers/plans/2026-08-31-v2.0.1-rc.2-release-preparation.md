# v2.0.1-rc.2 Release Preparation Implementation Plan

> **Execution:** Complete this plan task by task, preserve the stated stop boundaries,
> and record evidence before advancing. Checkboxes (`- [ ]`) track progress.

**Goal:** Prepare one exact-source `v2.0.1-rc.2` release candidate that can be published, qualified through Tier 3 evidence, and later considered for stable `v2.0.1` without transferring historical evidence.

**Architecture:** Keep release preparation separate from publication and stable promotion. The preparation pull request changes versioned package metadata, maintained documentation, and one focused regression test without changing production source; GitHub Actions remains the protected exact-head authority. After publication, the exact public RC2 wheel becomes the sole input to artifact verification, targeted canaries, and the fresh dual-profile Gate B campaign.

**Tech Stack:** Python 3.12+, `uv`, setuptools metadata, Markdown/OKF v0.2 documentation, GitHub Actions, GitHub Releases, PyPI trusted publishing.

**Spec:** `docs/quality/RISK_BASED_RELEASE_QUALIFICATION_DECISION_2026-08-24.md`

## Global Constraints

- Freeze preparation on `main@1cb4ca9ddd9d40d91e2c033ba8b816880323889a`; any later base requires a fresh delta review.
- Use tag and changelog version `v2.0.1-rc.2`; use PEP 440 package version `2.0.1rc2`.
- Preserve `v2.0.1-rc.1` documentation as immutable historical evidence.
- Classify RC2 as Tier 3 because the delta includes operator-configuration durability and maintenance Git-mutation integrity changes.
- Treat parent-directory fsync as best-effort after a successful atomic `.env` replacement: an `OSError` does not roll back the replacement, and that attempt carries no directory-entry durability claim.
- Keep stable `v2.0.0` as the default user recommendation until stable `v2.0.1` is separately authorized and published.
- Exclude open dependency-update pull requests from RC2 unless a separate reviewed decision changes the frozen base.
- Do not create a tag, GitHub Release, PyPI distribution, Gate B result, or stable-release claim in the preparation pull request.
- Keep `llms.txt` and `.well-known/llms.txt` byte-identical.
- Keep public prose vendor-neutral and maintainer-authored.
- Track the programme in milestone `v2.0.1 — RC2 Qualification and Stable Promotion` and issue `#548`.
