# GitHub Release — v1.13.1 (copy-paste)

**Title:** v1.13.1 - Logseq Matryca Parser 1.6.0 Alignment

**Tag:** `v1.13.1`

---

## Summary

**Parser alignment patch:** raises the minimum **`logseq-matryca-parser`** dependency to **1.6.0** so Plumber inherits the latest graph-integrity and headless-write fixes from the Logos Protocol release line.

**Why upgrade:** parser **1.6.0** (via **1.4.2** fixes) ships agent-write newline splice safety, resilient X-Ray state reload, SYNAPSE cyclic-embed truncation, and Clean Architecture graph APIs (`iter_attached_nodes`, `is_tracked_markdown_path`). Plumber mirrors the **1.4.2** newline normalization in `_headless_append_child` and preserves the corrupt X-Ray `ValueError` contract when the parser raises `SessionAliasRegistryError`. No MCP/CLI surface changes required.

Operators should upgrade with `uvx matryca-plumber` ≥ **1.13.1**. Point LLM hosts at **`llms.txt` v1.13.1**.

## Highlights

| Area | Change |
|------|--------|
| Parser pin | `logseq-matryca-parser>=1.6.0,<2.0.0` (was `>=1.4.0`) |
| Inherited fixes | Newline splice safety; X-Ray reload tolerance; SYNAPSE cyclic embed; `iter_attached_nodes` / `is_tracked_markdown_path` |
| Plumber parity | `_headless_append_child` trailing-newline normalization; `tab_size_for_node`; alias registry error mapping |

## Changed

- **`logseq-matryca-parser`** — minimum dependency **1.6.0**; inherits 1.4.x public API + graph parity.
- **`_headless_append_child`** — newline normalization + per-node tab size on headless OCC writes.
- **`load_alias_registry`** — maps `SessionAliasRegistryError` to existing corrupt-state `ValueError`.

## Upgrade

```bash
uvx matryca-plumber --version   # expect 1.13.1
uvx matryca-plumber --help      # resolves latest wheel from PyPI
```

Builds on **v1.13.0** (daemon/dispatch modularization + `GraphReadPort`). Architecture: [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md).
