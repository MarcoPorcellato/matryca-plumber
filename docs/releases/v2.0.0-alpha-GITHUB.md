## Summary

**Experimental alpha** for Epic [#20](https://github.com/MarcoPorcellato/matryca-plumber/issues/20): a daemon-owned **`shadow.sqlite`** read cache (FTS5 BM25 + recursive CTE subtree) behind **`MATRYCA_SHADOW_DB_ENABLED`** (default **off**). Logseq Markdown on disk remains the system of record; generational BM25 and parser subtree reads are unchanged when the flag is unset or shadow health is not `ready`.

**Why try it:** operators with large vaults who want sub-50 ms hierarchical reads can opt in, watch Sovereign UI `/api/state.shadow_db` health, and keep Markdown/BM25 fallback when shadow is disabled, lagging, or unhealthy. Duplicate `block_uuid` collisions surface bounded diagnostics ([#251](https://github.com/MarcoPorcellato/matryca-plumber/issues/251)) instead of silent corruption.

Operators should pin **`uvx matryca-plumber@2.0.0-alpha`** for evaluation. Point LLM hosts at **`llms.txt` v2.0.0-alpha** (§2.6 Shadow DB).

## Added

- **`src/shadow/`** — connection helper, incremental sync, FTS5 query, recursive CTE subtree, health meta, bounded `ShadowSyncError` diagnostics.
- **`ShadowGraphRepository` + `get_graph_read_port`** — routes reads through shadow when healthy; falls back to `MarkdownGraphRepository`.
- **Opt-in flag** — `MATRYCA_SHADOW_DB_ENABLED=false` default; parse-only in `src/shadow/config.py`.

## Changed

- **`search_graph(bm25)`** — prefers shadow FTS5 when enabled and healthy; invalid FTS syntax returns validation errors; backend failures fall back to generational BM25.
- **`read_graph_data(subtree)`** — prefers shadow CTE when enabled and healthy; falls back on flag off, health not `ready`, or SQLite errors.

## Fixed

- **Duplicate block UUID collisions** — bounded pre-insert diagnostics during bootstrap/incremental sync; message persisted in `last_sync_error`; no auto-dedup; no secret leak in error text.

## Upgrade

```bash
uvx matryca-plumber@2.0.0-alpha --version   # expect 2.0.0-alpha (PyPI 2.0.0a0)
# Optional — enable shadow read cache (experimental):
export MATRYCA_SHADOW_DB_ENABLED=true
uvx matryca-plumber@2.0.0-alpha plumber start --foreground
```

Builds on **v1.14.0** (catalog write-safety). Architecture: [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md). Roadmap: [`docs/roadmaps/ROADMAP_V2_SHADOW_DB.md`](../roadmaps/ROADMAP_V2_SHADOW_DB.md).

**Default-off guarantee:** unset `MATRYCA_SHADOW_DB_ENABLED` preserves v1.14.x BM25 + parser subtree behavior.
