## Summary

**Not an RC.** Ships the **P1 hyphenated FTS shadow query fix** ([#277](https://github.com/MarcoPorcellato/matryca-plumber/issues/277) / [#282](https://github.com/MarcoPorcellato/matryca-plumber/pull/282)) so natural compounds like `state-of-the-art` no longer mis-parse as boolean `NOT` or fall back to generational BM25 while shadow health is `ready`. Axis 4 FTS5 audit ([#280](https://github.com/MarcoPorcellato/matryca-plumber/pull/280)): **27 probes pass**, three original findings — **#277 fixed**; **[#278](https://github.com/MarcoPorcellato/matryca-plumber/issues/278)** (diacritic fold) and **[#279](https://github.com/MarcoPorcellato/matryca-plumber/issues/279)** (query length bound) **remain open**. Axes 5–7 on [#261](https://github.com/MarcoPorcellato/matryca-plumber/issues/261) remain open.

**Supersedes:** pin **`uvx matryca-plumber@2.0.0-alpha.3`** instead of `@2.0.0-alpha.2`. Prior alphas remain on PyPI (not yanked).

Logseq Markdown on disk remains the system of record; generational BM25 and parser subtree reads are unchanged when `MATRYCA_SHADOW_DB_ENABLED` is unset or shadow health is not `ready`.

## Highlights

| Area | Change |

## Upgrade

```bash
uvx matryca-plumber@2.0.0-alpha.3 --version   # expect 2.0.0-alpha.3 (PyPI 2.0.0a3)
# From 2.0.0a2 on the same vault — no schema migration; shadow.sqlite cache is reused.
export MATRYCA_SHADOW_DB_ENABLED=true   # optional — experimental
uvx matryca-plumber@2.0.0-alpha.3 plumber start --foreground
```

**Default-off guarantee:** unset `MATRYCA_SHADOW_DB_ENABLED` preserves v1.14.x BM25 + parser subtree behavior.
