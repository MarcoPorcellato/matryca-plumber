## Summary

**Not an RC.** Ships the **P2 FTS query length bound** ([#279](https://github.com/MarcoPorcellato/matryca-plumber/issues/279) / [#286](https://github.com/MarcoPorcellato/matryca-plumber/pull/286)): keywords over **512 Unicode characters** (post-`strip`) are rejected before FTS preparation or SQLite `MATCH`, with shared validation in acyclic `fts_validation.py`. Axis 4 FTS5 gate is **fully green** — **52 pass, 0 xfail** ([#278](https://github.com/MarcoPorcellato/matryca-plumber/issues/278) probe corrected in [#287](https://github.com/MarcoPorcellato/matryca-plumber/pull/287)). Axes 5–7 on [#261](https://github.com/MarcoPorcellato/matryca-plumber/issues/261) remain open.

**Supersedes:** pin **`uvx matryca-plumber@2.0.0-alpha.4`** instead of `@2.0.0-alpha.3`. Prior alphas remain on PyPI (not yanked).

Logseq Markdown on disk remains the system of record; generational BM25 and parser subtree reads are unchanged when `MATRYCA_SHADOW_DB_ENABLED` is unset or shadow health is not `ready`.

## Highlights

| Area | Change |
|------|--------|
| FTS query bound (#279) | `check_fts_query_length_bounded()` rejects overlong input before `MATCH` |
| Validation layering | `src/shadow/fts_validation.py` leaf module (no `query`↔`fts_format` cycle) |
| Axis 4 audit | **52 pass, 0 xfail** — A4-QUERY-07 diacritic contract corrected (#278) |

## Upgrade

```bash
uvx matryca-plumber@2.0.0-alpha.4 --version   # expect 2.0.0-alpha.4 (PyPI 2.0.0a4)
# From 2.0.0a3 on the same vault — no schema migration; shadow.sqlite cache is reused.
export MATRYCA_SHADOW_DB_ENABLED=true   # optional — experimental
uvx matryca-plumber@2.0.0-alpha.4 plumber start --foreground
```

**Default-off guarantee:** unset `MATRYCA_SHADOW_DB_ENABLED` preserves v1.14.x BM25 + parser subtree behavior.
