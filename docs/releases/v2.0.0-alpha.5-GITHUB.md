## Summary

**Not an RC.** Closes the v2-alpha Shadow DB hardening campaign ([#261](https://github.com/MarcoPorcellato/matryca-plumber/issues/261)): CTE depth-truncation status ([#289](https://github.com/MarcoPorcellato/matryca-plumber/issues/289) / [#291](https://github.com/MarcoPorcellato/matryca-plumber/pull/291)), state API absolute-path redaction ([#293](https://github.com/MarcoPorcellato/matryca-plumber/issues/293) / [#294](https://github.com/MarcoPorcellato/matryca-plumber/pull/294)), and Axes 5–7 audit probes. **No open P0/P1.** Also includes Graph Insights silent LLM fallback logging ([#114](https://github.com/MarcoPorcellato/matryca-plumber/issues/114)).

**Supersedes:** pin **`uvx matryca-plumber@2.0.0-alpha.5`** instead of `@2.0.0-alpha.4`. Prior alphas remain on PyPI (not yanked).

Logseq Markdown on disk remains the system of record; generational BM25 and parser subtree reads are unchanged when `MATRYCA_SHADOW_DB_ENABLED` is unset or shadow health is not `ready`.

## Upgrade

```bash
uvx --refresh-package matryca-plumber \
  matryca-plumber@2.0.0-alpha.5 read --help
# PyPI normalizes the pin to matryca-plumber==2.0.0a5 (PEP 440); help output does not print version.
# From 2.0.0a4 on the same vault — no schema migration; shadow.sqlite cache is reused.
export MATRYCA_SHADOW_DB_ENABLED=true   # optional — experimental
uvx matryca-plumber@2.0.0-alpha.5 plumber start --foreground
```

**Default-off guarantee:** unset `MATRYCA_SHADOW_DB_ENABLED` preserves v1.14.x BM25 + parser subtree behavior.

**Post-publish:** recommend a real vault soak (flag off + flag on) before promoting toward beta/RC (Epic [#20](https://github.com/MarcoPorcellato/matryca-plumber/issues/20)).
