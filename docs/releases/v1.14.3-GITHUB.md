# GitHub Release — v1.14.3 (copy-paste)

**Title:** v1.14.3 - Retry classifier, config-page race, and TUI observability fixes

**Tag:** `v1.14.3`

---

## Summary

**Small maintenance release.** Three low-risk fixes from the open issue backlog, each verified with a targeted `impact()` blast-radius check before merging. No MCP/CLI surface change; purely internal correctness and observability.

Operators should upgrade with `uvx matryca-plumber` ≥ **1.14.3**.

## Highlights

| Area | Change |
|------|--------|
| `llm_client.py` | Transport-retry classifier no longer catches `SystemExit`/`KeyboardInterrupt` |
| `memory_tools.py` | `store_fact` config-page creation is race-free (`O_CREAT \| O_EXCL`) |
| `tui_dashboard.py` | Scan-metrics / Phase-2 / snapshot failures now logged, not silently swallowed |

## Fixed

- **Transport-retry classifier** ([#202](https://github.com/MarcoPorcellato/matryca-plumber/issues/202), audit finding F6) — `call_openai_with_transport_retries` caught `BaseException` instead of `Exception`, momentarily routing `SystemExit`/`KeyboardInterrupt` through the retry classifier before re-raising. Narrowed to `Exception`.
- **`store_fact` config-page race** ([#43](https://github.com/MarcoPorcellato/matryca-plumber/issues/43)) — `_ensure_config_page` used check-then-write to seed `matryca-config.md`; two concurrent `store_fact` calls on a missing config page could race and clobber each other. Now uses an exclusive `O_CREAT | O_EXCL` create.
- **TUI dashboard silent failures** ([#125](https://github.com/MarcoPorcellato/matryca-plumber/issues/125), [#126](https://github.com/MarcoPorcellato/matryca-plumber/issues/126)) — scan-metrics, Phase-2 progress, and top-level snapshot collection swallowed `OSError`/`Exception` with no breadcrumb. Now logged via `loguru_logger.exception(...)` before falling back to prior UI values.
