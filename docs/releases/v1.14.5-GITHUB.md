# GitHub Release — v1.14.5 (copy-paste)

**Title:** v1.14.5 - Debugging campaign: complexity + temp-path hardening (supersedes v1.14.4)

**Tag:** `v1.14.5`

---

## Summary

**Small maintenance release.** Output of an advanced debugging campaign combining static analysis (bandit, semgrep security-audit + python rulesets), complexity analysis (radon), dead-code scanning (vulture), dependency audit (pip-audit), and PDG-based taint analysis. Two low-risk, verified fixes shipped; two higher-risk findings were documented as issues instead of rushed in (see below). No MCP/CLI surface change.

**Note:** the `v1.14.4` tag's release build failed CI (`ruff check`: line-too-long in a docstring introduced by that release) before the GitHub Release / PyPI publish steps ran. No `v1.14.4` artifacts were ever published — `v1.14.5` is the same content plus that one-line lint fix.

Operators should upgrade with `uvx matryca-plumber` ≥ **1.14.5**.

## Highlights

| Area | Change |
|------|--------|
| `importers/tana/convert.py` | No longer defaults to a predictable `/tmp/tana-vault` path |
| `graph/link_tag_hop.py` | `bfs_hops` split into three focused functions (ruff C901 resolved) |

## Fixed

- **Predictable `/tmp` default in Tana importer** (bandit B108) — `TanaConverter` fell back to a fixed `Path("/tmp/tana-vault")` when no `vault_path` was supplied, a symlink-race risk on shared/multi-user systems. Now mints a private `tempfile.mkdtemp()` directory when unconfigured.
- **Release-blocking lint failure** — shortened a docstring line in `_expand_bfs_frontier` past ruff's 100-column limit.

## Changed

- **`bfs_hops` complexity reduction** ([#233](https://github.com/MarcoPorcellato/matryca-plumber/issues/233)) — extracted `_resolve_seed_stems` and `_expand_bfs_frontier` out of `bfs_hops`. No behavior change.

## Not included (documented instead)

- **[#333](https://github.com/MarcoPorcellato/matryca-plumber/issues/333)** — `pickle` deserialization on the bounded-page-parse subprocess boundary (bandit B301 + semgrep). Real fix requires a wire-protocol change across both the multiprocessing.Queue and raw-pipe paths — too invasive to rush into a patch release.
- **[#334](https://github.com/MarcoPorcellato/matryca-plumber/issues/334)** — `process_llm_cycle_file` complexity F-grade (43), the daemon's worst hotspot. Flagged for a careful, isolated refactor rather than a quick patch.
