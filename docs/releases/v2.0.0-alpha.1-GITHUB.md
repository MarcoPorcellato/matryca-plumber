**Title:** v2.0.0-alpha.1 - Shadow DB Axis 1 Hardening

**Tag:** `v2.0.0-alpha.1`

---

## Summary

**Axis 1 hardening** on the experimental Shadow DB read cache ([#261](https://github.com/MarcoPorcellato/matryca-plumber/issues/261)). Builds on **v2.0.0-alpha** with cross-process writer coordination ([#262](https://github.com/MarcoPorcellato/matryca-plumber/issues/262)) and meta/pages health validation ([#264](https://github.com/MarcoPorcellato/matryca-plumber/issues/264)).

**Supersedes:** pin **`uvx matryca-plumber@2.0.0-alpha.1`** instead of `@2.0.0-alpha`. PyPI **`2.0.0a0`** remains published (not yanked).

Logseq Markdown on disk remains the system of record; generational BM25 and parser subtree reads are unchanged when `MATRYCA_SHADOW_DB_ENABLED` is unset or shadow health is not `ready`.

## Highlights

| Area | Change |
|------|--------|
| Writer coordination (#262) | Per-graph `shadow.writer.flock`; incremental timeout **10s**, rebuild timeout **120s**; SQLite `busy_timeout` clamped |
| Health validation (#264) | `ready` requires `shadow_meta` page counts to match `pages` rows — mismatch → `stale` |
| Audit probes | Axis 1 concurrency suite green with **zero xfails** ([#263](https://github.com/MarcoPorcellato/matryca-plumber/pull/263)) |

## Fixed

- **Cross-process shadow writers** — rebuild, incremental sync, and delete serialize on advisory flock; stale lock recoverable after process exit; different graph roots do not block each other.
- **Meta/pages mismatch** — FTS/subtree routing no longer treats torn meta as `ready`.

## Upgrade

```bash
uvx matryca-plumber@2.0.0-alpha.1 --version   # expect 2.0.0-alpha.1 (PyPI 2.0.0a1)
# From 2.0.0a0 on the same vault — no schema migration; shadow.sqlite cache is reused.
export MATRYCA_SHADOW_DB_ENABLED=true   # optional — experimental
uvx matryca-plumber@2.0.0-alpha.1 plumber start --foreground
```

**Default-off guarantee:** unset `MATRYCA_SHADOW_DB_ENABLED` preserves v1.14.x BM25 + parser subtree behavior.
