# Human-Governed Adaptive Retrieval Persistent Goal

Reach one evidence-backed terminal outcome for the human-governed adaptive
retrieval programme according to the canonical specification at
`docs/quality/HUMAN_GOVERNED_ADAPTIVE_RETRIEVAL_PROGRAMME_2026-08-16.md`.

First verify the live workspace, exact Git and Gist anchors, active policies,
existing issue state, Matryca Knowledge projection state, and saved delivery
work. Read the current authorized milestone exclusively from the execution
status ledger. If that ledger is missing, ambiguous, stale, or conflicts with
this goal, stop before execution. Do not redo milestones already proved by
exact current receipts in the ledger; never infer completion from the programme
text alone.

Proceed only through the currently authorized milestone and its
already-authorized local successors. Stop at every terminal evidence decision.
A `qualified_release`, `research_only`, `falsified_no_release`, or `superseded`
decision is a valid terminal outcome when supported by the stopping-gate matrix.
At A5, `qualified_for_runtime_integration` is non-terminal: record it, stop at
the separate A6 authority boundary, and never describe it as release
qualification or longitudinal evidence.

Do not alter hypotheses, thresholds, controls, acceptance gates, terminal
outcomes, scope, non-goals, invariants, privacy rules, claim levels, repository
ownership, or approval boundaries after observing results. Any such change
requires a separately authorized and reviewed protocol amendment.

Proceed autonomously only through read-only and already-authorized local work.
Pause before issue creation, commits, pushes, pull requests, Knowledge
projections, Gist edits, merges, tags, releases, or other external mutations
unless that exact action is separately authorized.

Use deterministic tools first. Delegate independent bounded discovery, tests,
documentation, and mechanical work to the lowest-cost worker that satisfies the
required capability, privacy, independence, and evidence class. Keep
architecture, security, privacy, scientific claims, integration,
qualification, and publication decisions with the primary reviewer. Serialize
overlapping writes.

Manage checkpoints and local branches within the authorized scope. Treat issue
creation, commit, push, PR, review, merge, Knowledge projection, Gist update,
tag, release, and external publication as separate gates. Never treat running,
skipped, partial, stale, mismatched, or unavailable evidence as a pass.

Record mutable progress only in
`docs/quality/HUMAN_GOVERNED_ADAPTIVE_RETRIEVAL_EXECUTION_STATUS_2026-08-16.md`:
current milestone, exact terminal evidence, behavior or claim impact, negative
or null outcomes, rollback state, residual risks, and next dependency. Change
the canonical programme only through a separately reviewed architecture or
protocol amendment. Ask only at an explicit user-authority boundary or when a
material scope change is required.
